# GLCKIO2 读取 CR3 页测试

## 测试
1. CCHWApi 2.9 控制寄存器取当前 CR3：
```
current CR3 = 0x20C952000
```
2. GLCKIO2 读取该 CR3 物理页：
```
membridge --device \\.\GLCKIo2 --layout glckio2 \
  --pa 0x20C952000 --size 0x30 --dump
```

## 结果
```
READ_OK bytes=0x30
0000: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
0010: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
0020: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
VERDICT=PASS
```
- 读取过程没有 BSOD；
- 没有 0x4E / 0x3B；
- 但内容全是 0，不是正常 PML4E 表。

## 解读
可能原因：
1. CCHWApi 控制寄存器返回的 CR3 不是真实页表根；
2. CR3 被加密/混淆；
3. 该物理页内容被 VBS 隔离为全零；
4. `MapPhysicalMemory` 对该页返回清零映射。

还需用已知真实 CR3（例如系统 CR3）对照。

## 价值
至少确认：
> GLCKIO2 是可以安全读取 CR3 物理页的候选驱动，不会像 HP/tdeio 一样在读页表时立即 0x4E/0x3B。

## 下一步
1. 用另一个已知 CR3（KPRL/KKYUM 获取）对照；
2. 对比 `PA=0x1000` 的 PASS 数据；
3. 验证是否 CR3 值问题，而不是驱动读问题；
4. 若 CR3 页可读，尝试页表翻译。
